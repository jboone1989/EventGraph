# Feature Specification: 值得看（Worth Your Time）实验栏目

**Feature Branch:** spec/worth-your-time-experiment-20261106
**Created:** 2026-11-06
**Status:** Owner-approved (owner-delegated Spec Review of c02a89f83ab2f3acaff784538fe9bf4ec51b1893)
**Target:** develop
**Input:** 用户希望让 EventGraph 实验一种帮助人们发现高价值内容的能力：AI 视频并非天然廉价，真正的问题是大量内容只有精美形式、缺少值得花时间的体验；将「值得看」作为独立实验栏目。

## 1. 产品假设与目标

内容生产成本下降后，读者的稀缺资源是注意力。实验要验证：在现有新闻与少量人工补充的外部内容中，能否每天挑出少量真正值得消费的内容，减少用户筛选时间。

- 栏目名：「值得看」/「Worth Your Time」，明确标注 Beta。
- 核心承诺：「少而值得」，不是另一条无限滚动信息流。
- 推荐的价值可以是情感、认知、审美、实用或趣味；不要求深刻，不因 AI 制作而贬低内容。
- 成功标准以用户看完后是否觉得值得为中心，不把点击、完播或停留时长当成价值本身。
- 这是独立内容策展实验，不改 EventGraph 既有新闻采集、分析、发布、评分或热榜。
- 与计划中的原创栏目「每天看看世界又整了什么活」区分：前者推荐原作品，后者生产原创解读；本 Spec 不实现后者。

## 2. User Scenarios & Testing

### User Story 1 — 每天只看少量精选（P1）

访客打开「值得看」，看到当天 0–5 条精选卡片；每条有标题、原始来源、推荐理由、体验类型、预估花费时间及清晰的原文入口。卡片可链接本站新闻，也可打开经编辑添加的外部作品（文章、视频或其他网页）。中英文栏目对应 /worth 和 /en/worth。当天没有足够优质内容时可以为空，绝不为了凑数自动填充。

**Independent Test:** 预置当天 3 条有效推荐以及一个空日期，验证双语页面、外链、空态、排序与导航。

**Acceptance Scenarios:**
1. Given 当天有 3 条推荐，When 打开栏目，Then 只显示这 3 条并分别可进入有效原始内容。
2. Given 只有 1 条满足筛选门槛，When 每日生成完成，Then 仅显示 1 条，而不是凑满 5 条。
3. Given 无有效推荐，When 打开栏目，Then 显示明确空态且没有伪造内容。
4. Given 英文路径，When 阅读卡片，Then 栏目 UI 与推荐理由为英文；没有可靠英文文案的条目不以中文冒充英文推荐。

### User Story 2 — 独立、低成本地发现候选（P1）

每天独立运行一次策展作业，从既有公开新闻中提取近期候选，合并管理员补充的外部链接；先作确定性去重与预过滤，再由现有模型配置做一次有上限的批量价值判断。只写入本栏目数据，不改新闻发布状态和主流水线。

**Independent Test:** 在模拟库中创建公开/未公开/重复条目及人工 URL，模拟模型成功、拒绝和超时，证明只产生允许的精选，新闻队列不受影响。

**Acceptance Scenarios:**
1. Given 新闻发布正常，When 策展模型失败，Then 新闻发布不受影响，栏目记录失败并保留以往已发布的历史精选。
2. Given 有同一事件的多篇报道或重复 URL，When 生成推荐，Then 同一天不重复推荐相同原始作品，且默认控制同事件重复。
3. Given 候选内容包含 AI 制作视频，When 评价，Then 不以「是否 AI 制作」作为排除项，只评价其提供的体验与可核对内容。
4. Given 模型返回缺证据的夸大推荐语，When 校验，Then 不公开该条推荐语；不可核实的心理效果不得作为事实陈述。

### User Story 3 — 轻量运营控制（P2）

管理员在现有后台中能查看候选与每日精选，可手工添加一个外部链接及其标题、内容简介、来源、类别、预估时间，可调整顺序、下架或手动发布。无需另建 CMS、运营平台或抓取工具。

**Independent Test:** 用现有管理员鉴权走添加、发布、排序和下架，访客只能读取已发布条目，且管理员操作有审计记录。

### User Story 4 — 判断是否真的节省时间（P2）

访客看过作品后可点「值得 / 一般 / 浪费时间」，可在本浏览器对同一条推荐更改选择。栏目后台能查看每天的推荐数、推荐点击与各类反馈数；不把反馈数当独立用户数。

**Independent Test:** 对相同推荐重复投票与修改投票后，只保留一个有效选择；统计结果与提交一致，未点击也可以选择反馈但统计会区分「反馈」和「已打开原文后反馈」。

## 3. Functional Requirements

- **FR-001 — 独立页面：** 提供 /worth、/en/worth 及桌面「更多」和手机「我的」可见入口；不取代首页、不改变现有底部五栏结构。服务端渲染公开数据并正常处理空态、手机端和外链。
- **FR-002 — 内容卡：** 最多 5 条/UTC 日，显示原始出处、可点击真实链接、短简介、推荐理由、价值类型和阅读/观看预估时间；缺少可验证时长时显示「时长未知」，不得编造。图库优先复用现有公开图片/媒体字段，缺图采用文本样式，禁止为了填图新生成图片。
- **FR-003 — 来源范围：** V1 自动候选仅取既有 publication 公共读取范围中可见、有效、有原文地址的近期作品；非公开、被撤下、未完成、仅热度信号的内容不可入选。管理员可以提交外部 URL 与必要元信息，但本版不自动搜全网、不抓社媒全文、不下载视频。
- **FR-004 — 独立作业：** 用现有 worker/调度能力每日运行一次（UTC 00:30；支持管理员手动重跑当日）。同一天重跑按内容规范化 URL/原始 item ID 幂等更新，已被手动下架的条目不得自动重新上架。策展失败不阻塞采集、analyze_article、publish 或事件分组；不增加这些流程的模型调用。
- **FR-005 — 成本上界：** 每天仅从不超过 30 个经确定性预过滤的候选中选择；默认最多 1 次批量模型请求，最多 1 次受控人工重跑请求（同日重复运行复用成功结果/回执，不自动无限重试）。走现有数据库动态模型配置、Provider 回执、预算熔断、费用诊断；禁止另建模型池或绕过熔断。模型不可用时只显示既有已发布推荐/人工发布内容，不伪造当天 AI 精选。
- **FR-006 — 策展标准：** 判断实际可能提供的情感、认知、审美、娱乐或实用价值，并考虑内容完整度、重复度、来源和理由的可核对性；热度、分数、视觉精美和 AI 来源身份均不得单独决定入选。理由为 1–2 句、必须基于已知内容，不声称用户必定受感动或已经看完。按内容多样性排序；不足量宁缺毋滥。
- **FR-007 — 人工补充与覆盖：** 复用现有 admin session/CSRF/审计机制，允许外链条目人工维护/发布/撤下，且手工决定比自动推荐优先；必须校验 http(s) URL、展示来源，不允许访客提交或调用任意 URL 抓取。保持操作简单，无新审批层。
- **FR-008 — 数据与发布：** 记录条目来源（站内 item ID 或外部 URL）、UTC 日期、可见状态、双语标题/理由、价值类型、估计时长、排序、选择来源（自动/手动）和修改时间。历史每日精选保持可访问，不因 UTC 换日删除。原始作品始终链接原地址；本站不转载外部全文。模型不直接在用户访问页面时调用。
- **FR-009 — 反馈：** 公开 3 档反馈；复用既有匿名浏览器会话与站点 POST 防滥用/限流能力，按条目+会话去重并允许修改；不要求登录，不额外做跨设备身份关联，不储存可识别访客画像。失败时给用户提示，不影响阅读。
- **FR-010 — 实验数据：** 在已有统计/后台表面增加栏目浏览、原文点击、反馈分布的展示，按 UTC 日汇总并区分「条数」「事件次数」「会话数（如果口径可验证）」；小样本标注样本量，不宣称点击或停留代表有价值。复用现有 analytics，不引入新 SDK。
- **FR-011 — 与现有功能隔离：** 不改变 /items、/story、新闻统一分析、热榜、首页 Hero、新闻评分、AdSense 策略或已有讨论模块；该栏目失败不得改变上述系统状态。
- **FR-012 — 可验证与撤回：** API 只返回已发布且仍合规可见的本站条目；后台下架后公开页面与 API 在现有缓存 TTL 内消失；重复作业、模型失败、双语缺失、重复来源、匿名重复投票都有聚焦测试。Beta 可通过隐藏导航入口停止曝光，保留历史记录，无需新部署服务。

## 4. Data Entities

- **Worth Entry（精选条目）：** UTC 日、本站 item 引用或外部 URL、真实来源、标题/理由中英字段、类型、展示顺序、预估消费时间、发布/撤下状态、自动/人工来源、审计字段。
- **Worth Vote（价值反馈）：** entry ID、匿名 session ID、三档选择、是否从栏目打开过原文、更新日期；每个 entry+session 最多一个有效票。匿名 session 只代表会话，不等于独立人。
- **Existing Publications / Provider Receipts / Analytics：** 复用当前事实与调用回执，不复制新闻正文或建立第二套新闻库。

## 5. Edge Cases

- 0 条候选、全部不合格、模型预算不足或限流：无凑数、无无限重试，运营可查到原因。
- 同一内容跨日期允许重新入选需有明确独立推荐理由；默认过滤近 7 天已入选原始 URL。
- 外部链接失效：运营下架/修复；V1 不建全网定时链接巡检。
- 已发布的站内条目后续变不可见：公开层不继续露出；外链按运营输入视为可访问，不声称自动核验全文。
- 英文缺失：该条不展示在英文页或只显示有明确标注的英文站外原始标题，不机译为已核验推荐。
- 浏览器禁用存储：允许反馈降级/提示，无法可靠去重时不得宣称每人一票。

## 6. Success Criteria & Evaluation

- **SC-001（体验）：** 每日 0–5 条且所有卡片可追溯到真实链接、来源、可审查的推荐理由；空日可以是成功结果。
- **SC-002（解耦）：** 策展模型故障、作业超时、管理员下架均不影响新闻进入、分析与公开发布；有自动化回归证据。
- **SC-003（成本）：** 默认每 UTC 日最多 30 个候选和 1 次批量模型请求；异常、重跑及回执可审计，新增调用总额可见。
- **SC-004（价值验证）：** 发布后连续观察至少 14 个 UTC 日，报告入选数、打开原文率、反馈样本数、三档分布、人工复核示例；样本少于 30 份有效反馈时明确写「仅探索性结果」。
- **SC-005（假设而非承诺）：** 预注册观察指标「值得」在有反馈样本中的占比及其随版本变化；不设缺少基线的虚假成功率目标，不以点击/观看时长代替该指标。
- **SC-006（完整性）：** 中英文、桌面/移动端、管理员 CRUD、投票去重、每日幂等及新闻流水线不受影响都有对应测试。

## 7. Non-goals / Constraints

- 不做全网社交爬虫、视频下载/转码、AI 视频生成、内容全文转载、登录/订阅、兴趣画像、个性化推荐、评论社区、无限滚动。
- 不为栏目新建一套队列、GitHub Action 调度器、模型绑定页、广告系统或运营后台。
- 不把每日精选强行发布到各个社交媒体；既有分发能力后续独立评估。
- 只实现并验证 develop 上的实验栏目；合入 main 和生产发布遵循原有 release 规则。
- 按现有 Spec Review 自动批准机制执行：本 Draft 先接受独立 AI Spec 审核，审核通过后由既有流程更新 Owner-approved 并合入 develop；无需在此文档提前自称已批准。代码实现必须引用合并后的不可变 Spec SHA。

## 8. Assumptions

- EventGraph 现有的公开新闻、匿名 analytics、后台管理、Provider 路由与回执系统均可复用；实际实施前在当前 develop 再核对接口和约束。
- 外部非新闻素材第一阶段由运营者手工输入 URL/元数据，因此实验开始时可能主要推荐新闻，不能声称已覆盖整个互联网。
- 栏目要观察用户是否认可推荐，不把 AI 的主观评分解释为人类价值的客观真理。
