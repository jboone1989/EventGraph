# 信源管理 · 删除与免原因操作

**Status:** Owner-approved
**批准依据：** 2026-11-07 网站所有者要求：信源管理支持删除；暂停无需填写原因，因为后台仅一人使用。

## 现状与目标

当前 `/admin/sources/:id` 只有暂停、恢复和编辑，且暂停必须填写原因。所有者明确撤销之前的软删除方案，改为直接硬删除信源及其相关历史新闻；确认操作前明确告知不可恢复，不添加 deleted_at 字段。

## 验收条件

1. 管理员在信源详情页可点击“删除信源”，明确告知后果并二次确认；不要求提供理由。
2. 删除直接移除信源记录和该信源的文章，信源从管理列表、统计和详情查询消失；已有或强制采集请求不能继续从该信源启动。
3. 删除操作清理该信源的文章和关联分析，删除确认明确告知数据损失；保留独立管理审计记录，不保留信源行。
4. 删除后的信源不可经普通编辑、预览、手动采集或候选自动复活再次启动；对候选的自动处理设置人工保持。
5. 暂停 / 恢复不填写理由；信源编辑保存也只需确认（同为单人管理的手动操作）。继续记录操作人、动作与变更内容，原因允许为空。
6. 删除使用当前记录版本，过期提交返回冲突，不覆盖其他更新；不存在或已删除资源返回“未找到”。

## 非目标

不重写信源采集器、队列、自动发现或公共新闻页面；不新增权限角色、复核流程或管理后台页面。

## 验证

- 数据库测试覆盖：删除可见性、停用、防强制采集、保留历史、审计、不重复删除、过期版本拒绝。
- 运行既有 TypeScript typecheck、Check、Docker、E2E 与独立代码评审。
- 实际开发环境部署和 UI 操作须另行验证，不能以 PR 合并代替部署确认。

> Owner 2026-11-07 修订：撤销原软删除及历史文章保留要求，改为硬删除（先验证关联外键），不得以 `deleted_at` 阻塞开发部署。
