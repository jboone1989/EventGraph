# EventGraph 后台：每日模型调用次数统计

**Status:** Proposed for owner-delegated Spec Review（用户于 2026-11-11 提出“需要统计下每天都调用了多少次模型”；不得将需求提出等同于对本文件每一项细节的人工批准）
**Target:** develop
**Scope:** 后台只读统计；沿用现有 Spec → Review → 任务入队 → GH-AW Worker → Check/Docker/E2E → develop 的原生流水线。不可直接部署生产。

## 1. 用户问题与既有事实

用户需要知道 EventGraph **每天真实尝试调用了多少次模型**，并识别“调用数很多但新闻产出不多”究竟是哪些模型、哪些失败/重试造成的。不能把当前三队列“失败条目数”或自动路由使用率当作请求次数。

2026-11-11 检查 develop：
- `database/migrations/0022_receipt_attempts_budgets.sql` 的 `receipt_attempts` 一行代表一次请求尝试（重试有新行），含 `service`、`model`、`status`、`started_at`、`usage`、`origin`，关联 `receipts` 的 `purpose` / `subject` / `request`。
- `packages/backend/src/providers/receipts.ts` 的 `paidRequest` 会在调用前记录 attempt；收到可用/不可用输出时更新状态；相同逻辑请求成功复用回执不再插入 attempt。它覆盖免费与付费模型，不代表只计收费请求。
- `providers/llm.ts`、`providers/embeddings.ts`、`providers/graphiti-proxy.ts` 已经通过上述路径记录主要生产模型请求。
- `packages/backend/src/admin/runs.ts::routingEffectOverview` 已按 UTC 今日统计**带自动路由标签**的尝试，不能作为全部模型请求的总数；`/admin/runs` 现有页面专注实时执行状态和失败重试。
- 部分手动测试/自动能力探测可能经注册模型测试路径而非 `paidRequest`，要明确区分，不可悄悄遗漏又声称“全部 HTTP 模型流量”。

## 2. 用户可见功能

1. 在现有 `/admin/runs` 页面、三队列之后、失败明细之前，新增只读 **“模型调用统计”** 分区，不新增后台顶级导航、另一个控制台、轮询器或写入接口。
2. 默认展示 **UTC 最近 7 个自然日（含今日未结束）**。可切换最近 30 日；有明显“UTC 00:00–24:00，今日仍在累计”说明，日期不随浏览器时区改变。刷新沿用页面已有 20 秒机制，不额外高频查询。
3. 今日指标：模型请求尝试总次数、成功次数、失败次数；“结果未知”计入失败指标并单独提示未知数量；“进行中”单独展示，不并入已完成失败/成功。总量 = 成功 + 失败（含 unknown） + 进行中。没有数据时显示 0；API/数据库错误时显示“无法获取”，**不得以 0 假装健康**。
4. 显示近 7/30 日**每日调用次数趋势**（日期 + 数值，图表或可访问的简单柱形呈现均可），点击/选择某天后展示该天按厂商+模型分组的统计表；默认选今天。当前日总数及日明细口径必须一致。
5. 明细至少展示“Provider/连接或模型实例标识（若可得）、模型名称、调用次数、成功、失败、成功率”，按调用次数降序。超长模型名省略/折行且保留完整查看；手机 390px 不挤掉统计列；超过一屏行数时复用现有 `DataTable` 与分页模式。不得把不同 Groq 连接的同名模型强行合并成同一**模型实例**，若历史记录没有稳定实例 ID 则明确标注“历史记录未区分连接”，而不是猜 ID。
6. 显示“重试/自动切换也会增加真实尝试次数；回执复用/缓存命中不会增加次数”说明。**生产模型请求**与“管理员测试/自动探测”分开：不能混进新闻处理总数。若测试/探测路径没有等价的准确请求级日志，明确标记其统计“未覆盖”，不可用能力测试条目数伪称为实际模型 HTTP 次数。
7. 统计只面向管理员，沿用现有鉴权；不暴露模型密钥、prompt、模型原始响应、请求体。默认无成本结算、无预算/额度配置、无导出和新监控系统。

## 3. 权威计数语义

- 权威来源是 `receipt_attempts` 的 `origin='live'`、`model IS NOT NULL` 记录，`started_at` 落入某 UTC 自然日，关联 `receipts` 提供目的、模型实例标签。不以新闻篇数、`receipts` 的逻辑请求数、任务数、最新状态数或 `routingEffect` 的自动路由子集替代。
- 一次真实调度到 `paidRequest` 的 attempt 记一次**请求尝试**，含重试、自动切换、厂商显式失败、超时结果未知、Embedding、Graphiti；即使接入端最终拒绝，仍按已有 attempt 语义计数。因配置错误/禁用或预算拦截**未生成 attempt** 的请求不记入；成功回执复用不重复计数。
- `status='received'` 计成功，`status IN ('failed','unknown')` 计失败，`pending` 计进行中；JSON/schema 无效会被 `rejectReceivedResponse` 记失败。同一天无数据是一组零，而不是空接口；历史状态以数据库当前审计记录为准。
- 具体模型实例优先使用现有注册模型稳定 ID：Graphiti 的 `receipts.request.modelId` 已有；聊天模型如当前未存，则后续调用可在 `requestSummary` 中补充`modelId`，不迁移旧日志、不改模型身份体系。分组优先实例 ID，次级 provider + model 名称，前端对历史组提供“未区分连接”提示。
- 对无法证明覆盖的非 `paidRequest` 调用做单独覆盖核查；如需补齐测试统计，应复用现有验证记录或可审计请求路径，经明确实现证据确认后才能标注准确。禁止为本功能新增调用模型、追踪请求正文、增加 cron、另造日志队列。
- 统计历史只覆盖数据库实际保留的 attempt 记录；不补造早期数据。窗口查询必须限定区间，避免整表扫描；只在有真实性能证据时新增在线索引。

## 4. 完整交互与状态

管理员进入运行与积压 → 页面显示今日指标和 7 日趋势 → 切到 30 日/选择一天 → 看到该日真实模型调用表 → 按真实统计识别失败/重试较多的模型。切换日期应同步更新标题、总数、表格和空状态；刷新后仍按所选日期显示（可通过 URL 查询参数保存状态，优先复用现有路由筛选）。没有该日记录给出“当天没有记录”；后端失败应明确报错并保留页面其余可用内容。不能让刷新清空用户选中的失败记录，不能影响“重新执行”按钮与当前三队列。

可访问性：统计标签、数字与日期可由读屏访问；桌面 1440px、手机 390px 均能查完整数据，长 ID 与模型名不压缩操作/数值。复用 `AdminPage`、`Card`、`Stat`、`DataTable`、`Select`/URL 参数与现有管理端样式；新增外部图表库需证明现有方案不能满足。

## 5. Given / When / Then 验收

1. **Given** 同一 UTC 日含 2 次收到回执、1 次明确失败、1 次结果未知、1 次进行中，**When** 查询日统计，**Then** 总尝试=5、成功=2、失败=2（其中未知=1）、进行中=1；日趋势和明细总数相同。
2. **Given** 一次自动路由失败后切换模型成功，并对另一个逻辑请求复用成功回执，**When** 汇总，**Then** 前两次均计数、复用不计新请求；不要求所有记录都有 `routing` 标签。
3. **Given** 两个 provider 连接各运行同名 Groq 模型，**When** 有稳定实例 ID，**Then** 作为两个模型实例分别统计；旧记录缺少 ID 时带“历史未区分连接”标志，不声称拆分成功。
4. **Given** 有聊天、Embedding、Graphiti 请求与无 `model` 的 Jina 请求，**When** 聚合，**Then** 前三类在生产统计中，Jina 不在；测试/探测不会冒充生产统计。
5. **Given** 请求恰在 UTC 00:00 前后创建且浏览器位于 UTC+8 / UTC-7，**When** 浏览 7/30 天，**Then** 仅按 UTC 日期分组，今日未结束的提示明显，前后端数值一致。
6. **Given** 今日没有任何 attempt、或 API 查询失败，**When** 打开页面，**Then** 分别明确展示“0 次”和“无法获取”，不混淆；数据刷新不会额外调用模型。
7. **Given** 30 天数据、长 provider/model 名、多模型实例、390px 手机屏幕，**When** 选日期、浏览明细/翻页，**Then** 数值与完整名称可追溯，页面布局可用，不把所有 30 日明细无上限传给浏览器。
8. **Given** 已有运行页失败条目和选中任务，**When** 新统计更新或切换日期，**Then** 三队列/失败重试功能保持原样，后台访问仍需管理员权限。
9. **Given** 完成实现，**When** CI + 独立评审 + 开发环境核对，**Then** PR 逐条列出测试证据、已核验的流量覆盖/未覆盖情况，绝不宣称未做的线上核验或生产部署。
