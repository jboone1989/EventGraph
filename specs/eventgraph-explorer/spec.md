# EventGraph Explorer + Story — 产品总规格 v1.0（待批准）

> **状态：DRAFT／规划基线，不代表功能已实现或用户已批准。** 日期：2026-10-20。目标分支：develop；固定起点：94bea40558de48ec8b9f172d87ec9c15bc7e42c5。关联 [Issue #61](https://github.com/jboone1989/EventGraph/issues/61)、[PR #70](https://github.com/jboone1989/EventGraph/pull/70)、[现有边界](../../docs/event-explorer.md)。批准后必须以**规格所在 commit SHA + 文件路径**冻结需求；实施 PR 不得自行偷偷修改已批准的规格。

## 1. 愿景与非目标

**产品承诺：** 用户不是被动读新闻，而是从一个事件、人物、公司或问题出发，亲手沿时间查看事件的形成、证据的累积、实体关系的变化，点击任何关系追溯到具体公开来源；多个 Agent 能读取同一份有界、可审核的证据包。不是只增加漂亮图表，也不是 AI 自动编造因果故事。

首要体验：「找事件 → 进入 Explorer → 选择历史时点 → 事件/关系/证据一起变化 → 展开原文 → 沿关系继续探索」。长期体验：「提出研究问题 → 得到基于真实证据的逐站 Story 路线 → 自由探索 → 导出结构化证据包」。

**范围外：** 另建图数据库/全图渲染引擎、重做 AIHOT 采集和事件树、点击网页时同步调用模型、无出处的关系推断、不可靠的“完整历史快照”宣传、改造 CI/CD 或插件架构、生产直接部署、为了展示效果填充演示/假事件。

## 2. 用户与成功条件

- **普通读者**：不必懂 Neo4j；一屏内看清「发生了什么、何时知道、为什么认为有关、证据在哪」，从首页/事件页能找到入口。
- **研究者**：区分公告发生日期与系统记录时间；能选择 known/valid，辨识冲突证据、修订、失效及数据覆盖缺口，能分享可复现的查询。
- **Ferro/其他 Agent**：拿到同一事件/时点下的来源、关系、时间语义和缺失数据标记；无法把模型推论自动升级为已证实事实。
- **移动用户**：390×700 或同等级窗口内单视图浏览（时间／关系／来源），点实体、证据可用底部抽屉，不需要在四个巨大面板之间滚动。
- **可证实的成功**：从真实开发入口进入真实事件，拖 T1→T2 后来源与关系同步变更，展开一条关系能找到原始 URL 和时间；独立浏览器验收、中文英文/桌面手机通过。数据不足则明确告知，不伪造通过。

## 3. 信息架构与核心界面

### 3.1 全站入口
- 提供醒目的 **Explore / 探索** 入口，支持首页或导航进入；将来以独立 Explorer 工作台承接事件/公司/人物检索和深链接。推荐路由 /explore、/en/explore；最终路由以现有路由/导航配置检视后确定，避免重复入口。搜索先复用现有站内搜索、知识中心搜索；不可把未经验证的自然语言 Agent 问答接成假搜索。
- 事件页 /story/:publicId 及 /en/story/:publicId 保留正文、索引与现有 SEO，同时提供明显的「在 Explorer 中探索」主动作；共享相同事件/时点/时钟查询语义。不出现两个行为相矛盾的时间机。
- 工作台桌面：主题/问题栏、事件时间控制器、聚焦图谱主画布、事件进展及右侧来源/关系证据面板；窄屏：时间／关系／来源 Tab + 底部证据抽屉。正文“当前综述”等只能在当前视角区单独展示和标注。

### 3.2 事件演化时间机器（P0）
- 来源时间段分组，上一阶段、下一阶段、滑块/拖动、自动播放/暂停；展示阶段新增报道、具体来源、简短摘要、原文链接与新增/结束关系（仅有可靠时序证据时）。
- 共享唯一显式时间状态 {storyId, asOf, clock, selectedEntity, selectedRelation}；拖动/切换/播放更新**承诺历史一致性**的全部视图，避免只移动滑块或只改变报道列表。
- 入口时默认最近已知时点；提供回到最新、回到中心、键盘操作、加载/错误/无数据提示。时间切换后旧关系与旧证据不能短暂漏出。

### 3.3 来源证据面板（P0）
- 点报道/节点/关系显示来源名称、标题、原文 URL、报道发布时间、系统首次发现/记录时间（存在才展示）、Graphiti 关系陈述、是否失效/存在争议、当前公开状态及数据限制。
- 清楚区分 **原始报道、模型提取的断言、模型候选推论、已核实的因果关系**；不能仅因图中的连线或共同出现即判定因果。引用不是逐字引语时不能加引号冒充。
- 支持点原始来源核对；撤回/删除/未发布/私有证据始终不出现在公开结果，即使回放过去也不重新暴露。无证据关系不显示；没有来源时不生成“可信度 100%”。

### 3.4 聚焦式交互知识图谱（P1）
- 默认只显示中心节点与少量经公开证据支持的一跳关系；点击按需邻域展开、聚焦下一节点、返回中心。关系类别/时间范围/强度过滤仅在数据确有字段或有合理规则时提供。
- 同对实体一条主连线，点击展开独立事实与来源；当前关系视觉高亮、选中实体档案与图谱保持上下文；节点位置稳定，平滑移动视野，不在每次展开全图重绘。
- 区分「事实关系」与「候选/推断关系」：后者如无明确记录或产品政策，不在公有图谱中渲染成同等事实。图谱不足时允许从来源列表继续阅读。

### 3.5 双时间历史回放（P1，高风险）
- **known**（当时系统已知）：报道使用首次发现时间；图谱只展示 asOf 前记录、且当时未过期并在**现在仍允许公开**的事实。后来的内容、关系、修订不能偷渡到以前。
- **valid**（现实有效期）：按事件有效时间 valid_at/invalid_at 重建，是事后视角，**不等于当时知道**；报道的 published_at 不是关系的有效期替代物。
- 实现只能声明 **bounded reconstruction（有界重建）**，直到不可变版本/修订账本及实体合并时间语义通过真实数据审计。时钟切换必须显著说明区别；缺失时间戳不猜测时间，不倒填；关系/文章上限及覆盖范围要显式显示。
- Graphiti 不可用/不支持 temporalSupport=bitemporal-v1 时：关系区 fail-closed，提示仅能回放报道；不得把当前图谱伪装为历史。已过期/更正关系显示其历史状态和证据，而不是删除审查痕迹或泄露撤回内容。

### 3.6 知识探索画廊与 EventGraph Story（P2，后续独立交付）
- **探索画廊**：可按主题发现精选的真实事件路线卡，含真实图/来源、阶段数量、更新时间；不使用伪造实体图谱作封面；可从卡片进入 Explorer。
- **EventGraph Story**：输入问题（例「某 AI 技术怎样从论文走到产品？」），从证据检索出可解释的多站路径，逐站展示论文/公告/技术突破/产品/市场影响（这些只是可能的阶段，不强制套模板）。每站需时间、实体、关系、至少一条可访问公开来源、置信/不确定性依据、下一步建议；用户随时跳出路线探索图谱。
- 先提供可复现的 **结构化证据包**，再做可选模型解说；网站浏览/拖动时不得触发付费 LLM，解说必须走既有 worker/provider 及预算闸，不能为 AI Story 复制 RAG 系统。公共 API/MCP 使用同一个 publication 公开读层。
- Story 不能将图谱关系当作因果链；证据不足时中断路径或标注未知，不凑满阶段；自然语言查询失败时给来源检索结果和明确降级，不虚构答案。

## 5. 需要独立确认的数据协议

- 现有接口优先：GET /api/site/stories/:publicId、GET /api/site/knowledge/stories/:publicId?asOf={ISO8601}&clock=known|valid、公开邻域/关系搜索；不得为相同数据新建第二套图谱接口。
- 显示层统一读模型建议：{subject, asOf, clock, fidelity, coverage, reports[], entities[], relations[], evidence[], missingFields[], truncated, sourceRevision?}。这不是已经实现的 API schema；实施 Agent 先核对现有 packages/contracts 并只增加必要字段。ID 与分页方式遵循已有 API。
- 证据包里的 **timeRecorded、timeEffective、sourcePublished、sourceDiscovered、sourceRevision、asOf** 不得混淆；字段缺失用 null/明确缺失原因。所有时间 ISO 8601 时区明确。
- Graphiti 边或实体是后续可变对象；没有保留过的历史版本不得承诺可恢复，金融决策复盘模式必须标示不能严格 point-in-time。
- 若候选时间早于当前数据库最早收录时间，显示「无法恢复此前资料」，不能凭今天数据补齐。
- 缓存与公开权限：按当前公开/撤回规则过滤，更新/撤稿后缓存不得重新泄露历史来源；禁止为私有内容创造历史永久链接。

## 6. 阶段放行与验收证据

- **S0 → S1**：外网开发链接可访问，至少一个真实事件具备可见入口、来源列表；明确开发运行 SHA 与 GitHub SHA 的区别。
- **S1 → S2**：EG-03 到 EG-10 在真实事件（至少 3 篇不同时间/来源，至少一个后来出现的图谱关系）下有 T1/T2 录屏或截图、浏览器请求与原始引用；若真实样本不足，诚实标未验收，不得靠 mock 关闭 Issue #61。
- **S2 → S3**：用户用图谱真正找到一条新的有源关系；同一证据包从网站和 Agent 查询一致；确认无权限泄漏。
- **S3 完成**：至少一条真实研究问题到 Story→图谱→原文的完整路径、无编造事实与自动付费调用，提供中英/手机证据。
- 每个阶段在 feature 分支独立 PR→develop、通过已有 Check+E2E、独立 Review，合并后删分支；开发机以真实 digest+HTTP+浏览器结果验收，不得因为 docker ps/CI 成功宣称产品完成。main 仅按既定每周发布。
