# Spec · 精简新闻主流程与中英文同步生成

**日期：** 2026-11-05
**状态：** 用户在对话中明确同意精简新闻流程，并指出中文来源缺少英文标题、摘要。
**范围：** EventGraph 新闻采集后的分析、普通动态发布、英文稿件落库；不变更模型 CRUD 与事件知识图谱架构。

## 问题
现有一条新闻分别执行预筛、双次评分、结构提取、中文稿件生成、英语补写等请求；日常集中处理数百条新闻时，很快耗尽免费模型额度。英文标题摘要由另一个计划任务补写，中文来源可能已公开却始终没有英文稿。

## 验收标准
1. 单篇新闻一个输入版本的基础编辑判断由**一次带回执的模型请求**完成，得到相关性、0–100 分数、结构化事实、中文标题摘要、英文标题摘要；不再为该版本串行运行原来的预筛、双次打分、结构提取、摘要模型链。
2. 两种语言都由输入原文约束，不能增加原文没有的事实或把中文当英文；模型输出不符合英文规范时保持缺失并进入既有补写队列，不能伪装成英文成功。
3. 同一版本重试复用已接收的回执，同一分析请求不得重复计入多条业务模型调用。
4. 普通动态在基础分析完成后即可进入公开信息池；事件归组、精选去重与 Graphiti 仍异步处理且失败不能阻塞普通动态；不擅自将未确认的归组候选推送为精选。
5. 保留现有信源许可、历史导入、缺少证据拦截、中文正文与作者原帖、精选门槛、原文引文落地校验。
6. 已发布新闻的更正与历史内容继续走现有英语补写任务；新分析中的合法英语稿直接写入 `english_copies`，沿用现有输入哈希作版本失效机制。
7. 基础分析主链路目标为每篇每个版本一次成功模型调用；备用模型重试、英文历史补写、事件归组和 Graphiti 必须在后台独立统计，禁止静默无限重试。

## 测试
- 集成测试：中文原文在一次分析调用后得到中英标题摘要，且英文版能读到；相同版本重新运行不产生新调用。
- 测试：评分、精选、无正文、不同信源、事件归组与翻译更正后仍保持合理行为。
- PR HEAD 的 typecheck、测试、Docker、E2E 必须通过才能合并；完成代码不等于已经生产部署。

## 优先复用
`editorial/analyze.ts`、`editorial/english.ts`、`jobs/content.ts`、`publication/publish.ts`、现有 `receipts` 和 `english_copies`。不创建新的模型服务、队列引擎或翻译数据表。
