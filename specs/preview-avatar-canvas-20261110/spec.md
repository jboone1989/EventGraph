# VM13 preview browser acceptance: optional avatar failure and issue-dot animation

**Status:** Owner-approved (owner-delegated Spec Review of e555503cc727442136042586e28dde21d851f849)

## Problem and evidence
On the latest merged develop release `b9545df67e2b00c7c18e72d6261b407a06d325f3`, GitHub Actions run `42801568062` successfully published and deployed VM13, but online browser acceptance failed on two attempts. The English daily repeatedly requested a third-party Bitcoin Magazine source avatar through signed `/api/img-proxy?mode=avatar-48` and got 502. On a later attempt, the Chinese daily also logged `IndexSizeError: CanvasRenderingContext2D.arc radius provided (-7.54952e-16) is negative` during the issue-dot entrance animation. The pages themselves returned 200; all functional tests and source SHA health checks passed.

## Requirements
1. **Optional source avatar fallback only**: the signed image proxy still validates signatures and URL restrictions first. If upstream fetch/decode of `avatar`/`avatar-48` (and any other existing `avatar-*` rendition) fails, provide an HTTP **204 No Content**, with `Cache-Control: public, max-age=60` (or shorter), `X-Img-Proxy-Fallback: unavailable`, and safe `X-Content-Type-Options` headers, not a 502. The browser's existing `SourceAvatar` `onError` displays the source initial; this is not an article content image. Log the original upstream error including host and image fingerprint server-side as before. Do not produce fake image data or a misleading success/304. Do not mask `ImageBudgetExceeded` or return fallback for article images, thumbnails, OG, full or any non-avatar modes. An invalid/expired signature still returns its existing 400/403 response; a valid successful avatar is unchanged.
2. **Issue-dot geometry**: floating-point roundoff at animation start makes the easing function barely negative and calls `ctx.arc` with a negative radius. Clamp the easing result (minimum zero), preserving the overshoot animation for valid progress; do not globally silence Canvas exceptions or suppress the browser-acceptance console checks.
3. **Regression tests**: cover at least `easeOutBack(0)` and its sampled `[0,1]` values for nonnegative results, and preserve >1 easing overshoot where present; cover optional-avatar failure and signature validation without weakening success semantics for article images or rate-budget failures. Verify repeated VM13 live browser smoke passes with original strict policy for errors, HTTP failures and layout. If upstream image is still unavailable, the avatar must genuinely display fallback instead of a broken request.
4. No migration, new provider, extra background scheduler, changes to news queues, or change to model routing `#541`. This is a follow-up **deployment acceptance bugfix** scoped to the two observed defects, with normal Spec-first review, code CI/review, merge to `develop` and VM13 preview validation only. Production `main` not changed.
