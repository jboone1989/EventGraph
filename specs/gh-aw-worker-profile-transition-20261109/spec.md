**Scope:** GitHub-native GH-AW control-plane bootstrap only, no application/production deployment code.

## Required behavior and bootstrap
1. **No destructive Policy migration.** Never edit the `work-queue` branch or `work-queue.jsonl` directly; no `clear`, `--hard`, cancel-work/cancel-claim, synthetic Result, forged release, queue rename, duplicate queue, privilege bypass or weakening of GH-AW contract checks. Preserve all pre-existing Work IDs, graph IDs, Issues, Claims, policy epoch, fairness and slot limits.
2. **Version incompatible authority explicitly.** Restore the original `eventgraph-worker` source/compiled lock to its previously approved **contract-compatible** network boundary for old Work, and add the new `eventgraph-worker-v2` as a *separate authorized GH-AW profile* carrying the existing enhanced `node` npm egress, GLM-5.3, limits, one-PR safe outputs, same strict assignment checks and single-job resource scope. No new dispatcher/queue/cron runtime. Reuse a shared prompt/body if doing so does not alter the verified prior worker contract or change GH-AW execution semantics; generated `.lock.yml` must be compiled using pinned official GH-AW v1.0.1 and committed, never hand-edited.
3. **Single queue, dual-version transition.** Update the existing official Dispatcher route authorization to allow either installed worker as decided by the native scheduler, still `max_dispatches: 1` and at most one open `agent-work` PR. The native Producer must choose `eventgraph-worker-v2` for **newly merged owner-approved Specs**, using a verified versioned worker profile and the CLI's trusted profile installation, without trying to rewrite Policy default. The old default Worker remains available for previously committed Work; do not modify old immutable assignments. Reject absent/mismatched versioned profiles, unknown trusted GitHub source, or wrong repo instead of fabricating a contract string or bypassing native admission.
4. **Fix the other half of the lifecycle.** A worker-route deployment may only report `available` if its profile matches the policy-installed identity/contract, or is a separate approved new profile. Add a preflight to prevent future incompatible same-name Worker redeployments and explain the proper versioned migration path. Avoid relying on a green `deploy` job if `expected_contract` and actual `profile.logical_contract` differ.
5. **One-time non-agent bootstrap.** The native queue currently cannot admit the task that would repair it. After independent Spec approval and merge into `develop`, install control-plane changes through **one ordinary non-`agent-work` feature PR** with standard Check, Docker, E2E and independent code review. Promote that reviewed control-plane code via ordinary `develop -> main` merge commit; do not direct-push main. No paid Worker dispatch before source and deployment contracts reconcile.
6. **Complete original work.** Recover Issue #530 from its *original immutable approved Spec* `specs/prod-hot-ranking-release-gate-20261109/spec.md@874078a95e44b3c84791a36279f46a39a65550cf` through the same Producer, without creating a duplicate Issue/Work identity. On successful native `submit-graph`, verify a real committed `Work` with `worker_profile=eventgraph-worker-v2`, a matching native PoolInstall/Deployment and a scheduler-visible status; only then allow one native Dispatcher launch. Existing Issue #490/#477 and other Work must remain eligible or explicitly blocked under their own preserved contract. Do not falsely claim product fix before a reviewed Agent PR and real production smoke pass.
7. **No production-side mutation in this bootstrap.** Do not alter `EVENTGRAPH_PROD_AUTO_DEPLOY`, VM09, main application source or release smoke rules. Do not migrate/clear database records. Only existing GitHub CI/CD may later perform an authorized production deploy.
