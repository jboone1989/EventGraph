# 内容资产与知识层增强（Content Assets）规格 v1.0（随 PR 提交）

> **状态：Draft，随实现 PR 一并提交（使用者 2026-10-24 指示「前面说的都做」）。** 本规格对应 `specs/002-adsense-readiness` 通过后的下一批改进：把「能过审」变成「值得读、值得回访、有独家物」。
> 分支 `feature/content-assets`（自 develop `d52f9a2` 切出）；实现 PR 引用本文件路径。

## 1. 背景与目标

AdSense 就绪整改完成后，站点在合规面已经达标，但三件事仍限制上限：

1. **读者看不到「谁在策展」**——收录决定只存在后台审计里，页面没有人的痕迹；
2. **知识图谱是最大差异点，却没有被读者看到**——`/knowledge` 以交互画布为主，服务端几乎没有可读文字，中文页甚至不在 sitemap 里；
3. **内容结构缺少「人写的层」**——日报综述是模型写的、受 grounding 约束不评论；没有编辑手记、没有主题简报，回访理由主要靠事件流本身。

目标：在不扩大内容政策风险的前提下，补上「人的痕迹、可读的知识、主题级入口」，并把守护检查自动化。

**范围原则**：本规格只做不需要外部账号/凭证、且能在本仓库内验证的改动。需要邮件服务、IM 机器人或新数据源的，单列 Phase 2（见 §6），避免半成品。

## 2. 用户可见行为

### 2.1 收录归属（FR-001/002）

- 事件页在「N 篇报道 · M 个来源」一行旁显示 **「编辑策展于 YYYY-MM-DD」**（仅当该事件至少有一条报道被编辑确认收录时）；英文页显示 "Curated by the editor on …"。
- 条目页同样显示该行（仅当该条目被策展收录）。
- 事件页对「单来源且综述过短」的快讯型事件显示 **「快讯」** 标记，与「热点事件/观察中」状态并列，让读者知道它没有事件级的编辑加工。

### 2.2 快讯型事件（FR-003）

- 判定与既有收录门槛同源：**单篇报道且 AI 综述少于 `SEO.minSingleSourceDigestChars`** → 事件页标记为快讯；页面照常可读、保持 `noindex`（既有行为），不新增收录。

### 2.3 编辑手记（FR-004）

- 日报页在报头之后、正文之前显示 **「编辑手记」** 区块：运营者按日期写的一小段话（2–4 句），署名「编辑」；英文日报页只在提供英文手记时显示（不把中文手记当英文）。
- 手记数据放在 `site/editor-notes.ts`（日期键 → `{ note, noteEn? }`），随部署生效；未配置的日期不显示任何占位。

### 2.4 主题简报（FR-005）

- 主题页在标题与条目列表之间显示 **「本主题跟踪什么 / 看什么」** 简报卡片：一句要点 + 3 条要点（跟踪范围、关键变量、常见误读），标注更新日期。
- 首批覆盖 6 个头部主题：`ai-models`、`ai-infrastructure`、`ai-agents`、`stablecoins`、`regulation`、`macro`。简报内容是常青编辑文案（不是新闻结论），中英各一份；英文页只用英文文案，没有则整块不显示。

### 2.5 知识图谱变化视图（FR-006/007）

- `/knowledge` 页面新增 **「最新一期图谱变化」** 区块（服务端渲染文字）：新增关系 / 失效关系 / 新实体计数，列出前若干条有来源的关系统（主体 → 谓词 → 客体 + 事实说明），并链接到当期日报与日常档案。
- 数据来自既有 `/api/site/knowledge/daily/:key` 与最近一期日报（无数据时整块不显示，不出现空壳）。
- 中文 `/knowledge` 加入 sitemap（与英文版一致）。

### 2.6 研究栏目入口（FR-008）

- 手机「我的」页（`/more`）出现「研究」一行，链接 `/research`（桌面侧栏已有；此前手机只能绕道「关于」页）。

### 2.7 守护检查（FR-009/010/011）

- CI 的 `check` 任务运行 `npm run adsense:preflight`：政策页占位词或缺失联系邮箱会让 PR 失败。
- `scripts/production-smoke.py` 增加：政策页占位词扫描、sitemap 全部条目带 `lastmod`、`robots.txt` 含两个 AdSense 爬虫段；当 `SMOKE_EXPECT_HTTPS=1` 时，检查 `http://` 与 apex 域名的 301 归一。
- 新增 `npm run curation:report`：输出最近 N 天的收录覆盖率（可收录条目/事件、被排除、待策展），用于运营复盘。

### 2.8 信源补强（FR-012）

- 新增 3 个已验证可抓取的 T1 一手源：**国家统计局「数据发布」**（中文）、**国家统计局 English Latest Releases**、**英国 FCA News**（RSS）。
- 首个中文官方统计源，补上「用一手数据核对二手报道」的能力；种子脚本只插入新源，不覆盖已有配置（与 `docs/deploy.md` 一致）。

## 4. 非目标

- 不做邮件订阅/newsletter、Telegram/飞书公开频道推送、政策与数据日历（Phase 2，需要外部账号与独立的隐私/同意设计）。
- 不新增评论、社区、会员、付费墙。
- 不改精选评分、信源参与模式或 AdSense 收录规则本身。
- 不做单来源快讯页的 URL 重定向/合并（会破坏既有链接，留作观察项）。
- 不把编辑手记做成后台编辑器（本版随 `site/` 文件部署；后台编辑列 Phase 2）。

## 5. 假设与依赖

- 编辑手记、主题简报由运营者撰写/审核；本规格只提供结构与渲染。
- `/knowledge` 变化区块依赖 Graphiti 数据与最近一期日报；无数据时整块隐藏（fail-soft）。
- 新信源随部署由种子脚本插入；不覆盖线上已有配置。

## 6. 后续（Phase 2，另立规格）

1. **日报邮件订阅**：发送服务、双确认订阅、退订与隐私页更新（与 AdSense 同意管理同一套合规考虑）。
2. **公开频道推送**：Telegram / 飞书群机器人，按条目分发。
3. **政策与数据日历**：把 BLS/Fed/ECB 的发布节奏做成结构化日历（需要新数据源或解析发布日程）。
4. **编辑手记后台编辑**：复用报告修订路径，让手记不必随部署更新。
5. **快讯页收敛**：单来源短事件在保留链接前提下合并或重定向到条目页。
