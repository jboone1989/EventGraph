# Repository-owned GLM review for EventGraph

Status: **Draft** until independent review and merge to `develop`; implementation must pin the approved merged Spec commit.
Owner direction: 2026-11-04 — each GitHub repository owns its own CI, review and deployment; no cross-repository review orchestration. Recorded in the PR discussion for this Spec.

## Existing behavior
- Before migration, EventGraph's `develop` caller forwarded **only successful `pull_request` or `workflow_dispatch` Check runs** to the reusable `livingruntime-remote` reviewer; the older default-branch `main` caller triggered on every completed Check. The develop caller used a job-level `if` to reject failed, cancelled or unrelated Checks before the external workflow started.
- **Live branch-ruleset check (2026-11-04):** EventGraph develop ruleset 25775731 currently requires `check`, `docker`, `e2e`, and `claude-review`, despite its historical name `Claude review paused` and the older Spec 014 description. Treat GitHub's current ruleset as authoritative. `.github/workflows/eventgraph-native-pr-closed.yml` also expects `claude-review`, so the migration must preserve that actual existing gate; reconciliation of obsolete Spec 014 descriptions is separate.
- In the develop caller, the job-level `if` excludes failed, cancelled and non-PR/non-dispatch Check runs; the central reviewer separately revalidates the source Check and immutable PR HEAD. `workflow_run` uses the **default branch's** trusted workflow definition; merging only to develop stages, but does not activate, the change.

- The official `anthropics/claude-code-action@v1` is **currently invoked by** [the external reusable review workflow](https://github.com/jboone1989/livingruntime-remote/blob/main/.github/workflows/eventgraph-glm-review.yml). This change brings the same reviewed invocation into EventGraph, not a new reviewer engine.

## Required behavior
1. Put the same GLM reviewer workflow, checklist and invocation in EventGraph, using the official `anthropics/claude-code-action@v1` and EventGraph's `GLM_API_KEY`. Use `vars.GLM_BASE_URL` with fallback `https://open.bigmodel.cn/api/anthropic` and `vars.GLM_REVIEW_MODEL` with fallback `glm-5.3` for this independent reviewer; the GH-AW Worker/Dispatcher's separately pinned endpoint is unchanged. Use a repository-local synchronous reusable workflow. Stage the new caller on develop; replace the cross-repository reference only when the trusted default-branch local implementation is promoted together, preserving the old path until then. Do not introduce a new central service, runner, worker, database or scheduler.
2. Only launch for successful PR-related Check completions, including validated exact-SHA `workflow_dispatch`, and verify the triggering Check ID, event type, successful conclusion, immutable head SHA and current in-repository open PR before the model receives secrets. Preserve independent read-only review, issue comment and `claude-review` commit status, including blocking findings and failure results.
3. Reuse the existing trusted `planReview` preflight to skip a repeated successful review **only when** the newest bot-attributed `claude-review` status matches the exact (head SHA, live base ref, live base SHA) identity; failed/missing/unattributable review never counts as success. A changed base or head forces a fresh review. Preserve manual re-review when explicitly authorized; don't treat unverified status as a bypass.
4. Do not run PR-controlled code with privileged credentials. The privileged `workflow_run` definition, reviewer working directory, Claude project instructions and model prompt must come from trusted default-branch files, never from a candidate PR. Check out the PR HEAD only into an isolated path, then move it outside `GITHUB_WORKSPACE` (such as `$RUNNER_TEMP/pr-head`) before invoking Claude. Keep Claude's cwd on trusted `main`; its project settings, hooks and `CLAUDE.md` must never originate from PR HEAD. The PR tree is only read-only diff/file evidence; do not execute scripts, hooks, PR-supplied tools, or arbitrary GitHub write tools. Disable all Claude hooks in action settings.
5. Preserve existing required status contexts (`check`, `docker`, `e2e`, `claude-review`) and current branch rulesets. Do not alter production images, deployment jobs, or `main` release policy. Remove/retire only the cross-repository entrypoint after local reviewer is active.
6. Keep the normal feature -> develop -> main release flow. Since `workflow_run` definitions are loaded from default branch, activation must be part of an **explicit controlled main release** without inadvertent production deployment; before then report the change as staged, not live.

## Acceptance
- Successful Check on a real in-repo open PR invokes only EventGraph's local review workflow, emits a `claude-review` status and blocks merge on invalid/important findings.
- Cancelled, failed or push Check never invokes the model. A previous success for the same head+live base skips model calls. Base changes and previous failures require review.
- Review loads its rubric exclusively from trusted default-branch `.github/review/claude-review-checklist.md`, never PR HEAD. The only checkout of PR HEAD is for read-only diff inspection. No runtime clone, checkout or reusable-workflow reference to `livingruntime-remote`.
- An adversarial PR adding `.claude/settings.json` hooks and changing `CLAUDE.md` cannot execute its hook or alter the trusted model instructions, even when `GLM_API_KEY` is present. Test reviewer cwd and isolated checkout path on a real review.
- Existing required CI checks and docs-only behavior work without new permissions or heavyweight runners.
- CI checks syntax and local workflow reference, and a real smoke run confirms the local review before deleting central ownership.
- No production deployment occurs as part of this migration.
