# EventGraph · 地区冲突影响追踪规划 v0.1

> **状态：2026-10-25 已记录的产品规划基线。用户同意保存，不等于授权一次性开发、部署或新增所有数据源。**
> 面向后续 ChatGPT、Claude、Pi 和开发者：开始讨论/实现前先读此文、核对当前仓库及运行环境，再从真实证据更新决策。不要依赖对话记忆复述，更不能把设想标成已完成。

## 一、产品目标与职责

从“新闻聚合 + 事件/实体图谱”走向**有证据、能沿时间回放的事件影响知识基础设施**，回答：

1. 地区冲突何时何地发生、如何演化？
2. 哪些政府/机构采取了什么政策，处于拟议、宣布、生效、修订或撤销的哪一阶段？
3. 哪些航线、港口、商品、能源和物流链出现可观察的变化？
4. 哪些公司有可核实的业务/工厂/采购/销售暴露；哪些经营后果被披露确认？
5. 相关资产和市场指标在明确时段怎样变化、有哪些不能归因于冲突的其他解释？

阅读路径：**事件事实 → 政策/供应链传导 → 企业暴露与结果 → 市场时间序列**，每一步都可看原始资料。**没有证据的环节必须中断，不要补画连线或用模型填空。**

分工：EventGraph 管理事实、来源、结构化关联和时间演化；Ferro/其他 Agent 提出竞争性因果假设、进行研究、反驳和预测，预测结论不得直接升格成 EventGraph 的已证实关系。这需要在正式开发前和 [编辑政策](../../docs/editorial-policy.md) 的既有产品边界达成一致。

## 二、已存在的基础与缺口

已检查的 `develop` 仓库：
- AIHOT/PG 的采集、去重、报道修订、`stories`/`facts`、跨文章分组，以及公开事实路线 `packages/backend/src/publication/story-route.ts`。
- Graphiti + Neo4j：`packages/backend/src/knowledge/graphiti.ts`、`knowledge_service/server.py`，实体、关系、Episode 和来源证据；**泛化的 RELATES_TO 不等于具体影响，更不是因果证明**。
- 事件时间线、EventExplorer、知识图谱、关系证据抽屉、known/valid 双时间查询；[已有时间回放边界](../../docs/event-explorer.md) 说明它是**有界历史重建**，并非历史版本的完整快照。
- 事件价格显示与 `market_snapshots`，目前针对新闻中提到的少量加密资产做时间窗口价格比较，不承担归因。

2026-10-25 cn-dev **只读快照**（不是生产数字，以后务必重新核实）：599 个事件、635 个事实、Graphiti 5,781 实体及 8,844 关系、972 次入图版本记录（951 篇不同文章）；近七天 `world` 类约 63 篇；行情仅 BTC/ETH/SOL/XRP/BNB，约八天历史、每 15 分钟一次。实际数据库 61 表未见专门的政策措施、供应链依赖或企业受冲击结构。cn-dev Web/API/Worker 当时仍在旧镜像 `sha256:c0f0c1a1…`，**源码功能≠已部署且验收的 UI**。

主要能力差距：
- 无权威政策“措施类型 + 适用对象 + 宣布/生效/结束时间 + 状态”的规范化视图；
- 无海峡/航线/港口/商品供给指标到企业实体的可信依赖证据；公开供应链数据库覆盖极不完整；
- 无可辨别“共同提及 / 事实关联 / 来源声称因果 / 实证结果 / 尚待证伪假设”的**影响关系语义**；
- 无能源、运价、股票、外汇及利率等跨市场历史回放；
- known（当时系统知道什么）与 valid（事后认定何时有效）双时间尚无法还原所有修订/撤稿/关系更新；
- 图谱规模不等于可解释性，真实跨层案例仍没有完成端到端验证。

参考已有文档：[knowledge-architecture](../../docs/knowledge-architecture.md)、[graphiti-integration](../../docs/graphiti-integration.md)、[knowledge-relation-review](../../docs/knowledge-relation-review.md)、[Explorer handoff](../eventgraph-explorer/handoff.md)、[亚洲及政策信源清单](../006-ops-control-plane/china-and-asia-source-inventory.md)。

## 三、数据语义（优先投影现有事实/图谱，再决定最小迁移）

| 层 | 需要的核心字段/指标 | 绝不能推断 |
| --- | --- | --- |
| 冲突事实 | 发生地/参与者/类型、来源 ID 与文章版本、发生/报道/首次收录时刻 | 同一地点或时间报道就是同一冲突 |
| 政策 | 机构、措施类别、目标国家/商品/实体、范围、拟议/宣布/生效/撤销等状态、各阶段时间与官方公告 | 政策提议等于已经生效 |
| 航运/商品 | 航线/设施/品类、指标值/单位、观测窗口、历史基线、覆盖率、异常或修订 | 港口拥堵就等于所有相关企业停工 |
| 企业 | 公司统一标识、可核查的设施/业务/供应依赖、正式披露与经营结果、各时点 | 文章提及企业就等于遭受冲击 |
| 市场 | 指标/证券/合约、交易所和单位、市场日历、时区、价格与量、采样频率、事件窗口 | 同步涨跌证明由该冲突造成 |
| 影响边 | 主体/客体、具体影响类型、证据与来源版本、证据等级、状态、有效/获知时间、更正记录 | Graphiti 共现 RELATES_TO 自动变成“导致” |

影响链至少区分：**可验证事实**、**来源明确声称的关系**、**客观暴露或依赖**、**分析假设**、**仅观测到的市场变化**。真实影响边应使用有含义的关系类型（如政策约束、航线中断、公司暴露、公开报告损失），但**不在 P0 新建第二套通用图谱**。先构建对单例的类型化查询/展示投影；如果现有 `facts` / Graphiti 无法保存关键状态与证据，再提出严格最小的 schema 变更。

每条边须能打开公告/报道/数据指标原文，注明适用时间、系统获知时间及来源是否已更新。纠错与证据缺失要原样保留；不得冒充历史全量一致性。

## 四、数据来源候选与准入规则

先用**合法且可维护的官方结构化 API/下载、RSS、授权来源及必要时的 Search/Fetch**；不为凑覆盖率重建脆弱网页爬虫。以下是研究候选，**不等于已接入或已获商用许可**：

- **冲突**：GDELT、ACLED，以及国家/多边机构官方公告。关注地理/参与方精度、报告偏差、更新频次和商业条款。
- **政策**：WTO Trade Monitoring、Global Trade Alert、各国外交/贸易/能源/海关/制裁主管机关的原始政策记录。尤其核验拟议/宣布/实施/结束四类时间。
- **贸易运输**：IMF PortWatch、UN Comtrade、海事/港口与能源机构。AIS 有信号缺失或干扰；贸易统计滞后，不能当实时企业供给。
- **公司**：SEC EDGAR、交易所公告、公司 IR、Open Supply Hub 等开放登记。工厂/公司名被匹配不代表存在真实供应关系。
- **市场**：现有 Binance/OKX，必要时少数正式可用的 EIA 能源数据与有许可的运价/股票/基准数据。统一口径、频率和开市日。

示例官方入口：[GDELT](https://www.gdeltproject.org/) · [ACLED](https://acleddata.com/) · [WTO](https://www.wto.org/) · [Global Trade Alert](https://www.globaltradealert.org/) · [IMF PortWatch](https://portwatch.imf.org/) · [UN Comtrade](https://comtradeapi.un.org/) · [SEC EDGAR](https://www.sec.gov/edgar/search/) · [Open Supply Hub](https://opensupplyhub.org/) · [EIA](https://www.eia.gov/opendata/)。

**源准入检查**：接口实际成功、历史跨度和最后更新时间、时区/单位、许可及广告站点商业展示权、缓存/再分发权、调用成本与限额、数据误差、合法的归属/引用。尤其 ACLED / Global Trade Alert 的许可不能默认为商业自由使用；无法复用时只提供合法元信息及原站链接，不绕过授权或付费墙。

## 五、分阶段最小实施路线

### P0 — 现有链路的真实性与积压（先消化数据，再扩源）

核对当前 `develop`、开发容器镜像、信源配置与实际数据库。以一组真实的地缘政治/政策/能源报道检查：发现 → 模型任务 → 事实抽取 → 事件归组 → Graphiti 入图 → 网站和 Agent 接口。记录数据吞吐、延迟、可用模型/阶段、失败原因；优先修核心阻断点。**不新建第二套后台、新闻引擎或图谱**。

### P1 — 第一个“事件影响档案”

复用现有 `/story/:id`、`StoryRoute`、`EventExplorer`、图谱和证据抽屉；仅给**有数据的**政策、供应链、企业、市场增设分层视图。政策必须有明确阶段与时间；所有影响边明确事实/主张/假设类型；无数据明确留空。英文/中文一致，390px 手机和桌面均能从事件钻取到来源证据。

### P2 — 一条能源航运垂直数据链

只选一条关键航线/海峡、少量能源/运价指标、少数有权威公司披露的企业。按需扩展已有 `market_snapshots`/`EventPrices`，展示 T0 前后、1 天、7 天等**有数据**的窗口、市场日历及可能的替代解释。若企业暴露无法核实，终止于航运/商品层，不填补公司的名字。

### P3 — 验证通过才逐行业扩展

跨事件比较政策变化、同一企业多次暴露、市场后续反应；跟踪反证、撤销与更正。然后才考虑半导体、关键矿产、粮食等领域。仅 Ferro 确实需要图谱 + 文章全文 + 事件树联合检索时评估引入 LlamaIndex；不提前部署。

## 六、最小可证伪实验：霍尔木兹海峡相关真实事件

选择一个能够核对发生时间与原始报道的**真实航道/地区冲突或中断案例**（优先霍尔木兹海峡，事实不满足则换真实案例）；不要预先假定政府采取了某项措施、某企业停产或油价变化由此造成。

样本限制：**1 个事件、1 条航路/海峡、最多 2 项核实政策、1–2 个运输/能源指标、最多 3 家有证据企业、少量价格基准**。确定 T0 / T1 / T2，演示：
- T0 当时已知事实与来源；
- T1 新政策、交通量/商品指标的真实更新；
- T2 有则显示企业披露与市场变化，无则显示证据缺口；
- 切换 `known` 与 `valid`，区分首次获知、事件有效与事后更正；
- 每条边可展开证据与反证，无证据不出现；用户可以沿时间与关系导航。

### 必须通过的验收

1. **零无来源影响边**：每条显示的事实/影响关系都有来源 URL、文章/公告版本、具体主体和时间；严禁根据共现生成因果。
2. 政策拟议/宣布/生效/撤销不会混淆，适用对象与日期得到官方文件支持。
3. 物流指标带单位、时间分辨率、基线与测量偏差（包括 AIS 局限）；不把物流下降写成企业停产。
4. 企业必须有可核查经营暴露；已确认业绩/生产结果与潜在风险分开。
5. 市场数据有交易日、时区、可比窗口及来源；不因波动同日发生便写“冲突导致”。
6. T0 的“当时获知”不能出现 T1/T2 才出现的消息；修订/撤稿无法精确复原处必须明确写“有界重建”。
7. **负例测试**：一个仅与地区/行业共现而没有依赖或受损证据的企业，不能被画出影响边。
8. Graphiti 或外部行情源不可用时降级为可阅读的事件来源；不使用伪造/过时数据补全图。
9. 双语以及桌面/手机交互完成真实浏览器验收，点击来源能回到原始公告与正确时间窗口。
10. 展示、缓存、再分发及将来的 AdSense 投放符合原始数据许可；不把自动摘要的“可索引”误作“广告可投放”。

**停项/调整标准**：若小样本不能构成至少一条可追证据的有意义的两跳跨层路径，就先修证据检索、实体消歧或产品定位，而不是扩大抓取/模型调用/全球图谱规模。此要求不是强迫补齐五层——证明某一层无证据，同样是合格的研究结果。

## 七、主要反对意见与未决事项

- **关系与因果**：普通 Graphiti 关系易误归属；此前 Omi/MSCI/Strategy 案例已证实主体归属错误可发生（见 `docs/knowledge-relation-review.md`）。
- **供应链覆盖**：公开供应商、客户、采购比例常常缺失，不能吹成全产业链。
- **时间穿越偏差**：新闻时序可以回放已存的记录，却不能虚构被覆盖的旧版本。
- **市场混杂因素**：相关不是归因，不能靠价格涨跌直接判断原因。
- **成本/许可**：商用数据库、深度企业供货图与金融时间序列都可能超出当前预算；优先复用。
- **产品职责**：EventGraph 面向所有 Agent 提供事实，不替代 Ferro 的因果分析；需明确更新编辑政策的叙述而不擅自发布预测。
- **独立审查状态**：2026-10-25 曾尝试用 Claude Remote 做方案反方审查，但会话 STALLED，**未取得完整结论；不能写“Claude 认可”**。仅在进入正式实施决策时重试一次，只读审查，不建额外框架。

## 八、后续 Agent 交接准则

1. **先读本文件**、已有编辑政策与知识/Explorer 文档，核对当时的数据源和仓库最新版；不能复用这里的历史环境数量当作实时结果。
2. Research First：先检索当前代码、上游 AIHOT、成熟数据提供方/API 与实际许可证，再提 schema 和新组件；考虑“直接复用/现有投影”这个最小选项。
3. 先建立**首个案例的一手证据矩阵**（每层出处/接口/数据粒度/许可/缺口），再从现有 UI 做一个真实薄切片；完成前不扩大数据源。
4. 按“事实、来源主张、暴露、假设、市场观测”审查每条边；加入负例与 known/valid 反例；必要时独立反方质疑。
5. **本规划保存不代表授权 P0–P3 开发**。需要实现时才拆任务/单独 PR；开发→`develop`，验证后再按既定规则发布；不因为 PR/CI 通过就宣称生产或开发环境已更新。
6. 任何新决定、更正和已验证的案例输出更新本文的后续版本或附有链接的任务；记录 commit/日期/证据/未验证项以便跨会话追溯。

## 九、最终成功标准

成功不是让 AI 自动解释所有地区冲突对全球每一家公司和所有市场的影响，而是让读者和其他 Agent **确切知道：证实了哪些影响，证据在哪里、什么时候才被知道，哪些链路仍未知，市场到底观察到什么变化**。验证一个真实案例之后再逐步推广。

## 十、案例验证记录（不改需求，只挂证据）

- 2026-10-27：首个真实薄切片完成——霍尔木兹海峡油轮触雷事件的只读证据矩阵（T06：五层×链路判定×许可×链接状态）与验收对照，见 [audit-2026-10-27.md](./audit-2026-10-27.md) 与 [validation.md](./validation.md)。结论：现有投影足够，未引入新表/新面板/代码；产品内政策、企业、市场三层为"无证据"层；站外一手文件可核政策阶段（封锁 07-13 宣布/07-14 生效）与航运指标，但四条相邻链路两条断链（事实→政策、航运→企业）、一条有据（政策→航运）、一条无对象（企业→市场），另有事实→市场直连断链（政策先于 T0、船舶隐名、基准滞后三处原因各有实据）；负例两条成立（新闻/政策层），企业共现负例未验证（产品内零具名企业），归组层事件混淆控制因一篇 gCaptain 稿尚无归组决定待复跑。
