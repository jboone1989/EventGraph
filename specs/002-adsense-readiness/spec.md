# AdSense 审核就绪（AdSense Readiness）规格 v1.0（待批准）

> **状态：Draft（2026-10-23 起草，待使用者批准）。** 批准方式：在本文件所在 commit 上确认；批准后以 **commit SHA + 本路径** 冻结需求，实现 PR 引用该 SHA，不在实现分支内私改已批准内容（`docs/spec-review.md`）。
> **Spec 目录**：`specs/002-adsense-readiness`；**建议实现分支**：`feature/adsense-readiness`（实现时从 `develop` 切出，按 `feature → develop → main` 晋级）。
> **输入**：使用者要求「写个 spec」。范围：把 https://livingruntime.com/ 从当前线上状态整改到**可以提交 Google AdSense 站点审核**、并在通过后安全开启广告的状态。

本规格只覆盖「达到可送审状态」的站点行为与验收；**广告运行时**（`adsbygoogle.js`、广告位、Auto ads、广告收入预期）不在本规格内，通过审核后另立规格。

### 1.2 为什么现在送审会被拒（官方条款对照）

| 官方条款 | 本站现状 |
|---|---|
| 复制内容：不得在「**without additional commentary, curation, or otherwise adding value**」的页面上放 Google 广告（[policy](https://support.google.com/publisherpolicies/answer/11190248)） | 多数页面主体是第三方报道的模型摘要 + 外链，编辑附加价值低 |
| 低价值/无出版商内容：不得在「**without publisher-content or with low-value content**」的页面放广告；不得在「**automatically generated content without manual review or curation**」上放广告（[policy](https://support.google.com/publisherpolicies/answer/11112688)） | 采集 → 模型 → **自动发布**，无人工确认；单来源短页大量存在 |
| 被 AdSense 直接引用的搜索垃圾政策：转载「**or even citing the original source**」不豁免；「automated transformations like synonymizing, **translating**」「**Reproducing content feeds**」在违规例子里（[policy](https://support.google.com/publisherpolicies/answer/11035931)、[spam policies](https://developers.google.com/search/docs/essentials/spam-policies)） | 英文稿由模型批量生成并自动发布；以 RSS/网页为原料规模化产出 |
| 隐私披露：必须有隐私政策并披露 Google/第三方 Cookie、标识符与退出方式（[policy](https://support.google.com/publisherpolicies/answer/10437794)） | 政策页未填完，无联系方式 |
| 站点就绪：HTTPS、可抓取、AdSense 爬虫不被屏蔽（[未就绪原因](https://support.google.com/adsense/answer/12176698)） | 三入口未归一；无 HSTS；AdSense 爬虫未被显式声明 |

### 1.3 目标

整改后，站点必须能对一个普通审核者（和自动化检查）给出三个可核验的答案：

1. **谁在运营**：真实的运营主体、公开联系方式、完整的隐私政策与使用条款、编辑方针与 AI 使用披露。
2. **内容有什么额外价值**：被索引的页面经过人工策展；聚合页有编辑确认与来源归因；存在署名的原创分析（含站内独家数据）。
3. **技术是否就绪**：单一规范域名、可抓取的 sitemap、AdSense 所有权验证、面向 EEA/UK/CH 的同意管理，以及「审核通过前不加载广告」的门控。

## 2. 用户场景与测试（User Scenarios & Testing）

### 2.1 场景 1 — 审核者确认这是一家真实运营的网站（P1）

作为 AdSense 审核者/自动化检查，我打开站点任意页面，应当能确认网站在合规地、有人负责地运营。

- **Given** 任意公开页面，**When** 看页脚，**Then** 能看到「隐私说明 / 使用规则 / 联系我们」三个入口。
- **Given** 打开 `/privacy` 或 `/terms`，**When** 阅读，**Then** 有运营主体、联系邮箱、生效日期、版本，且没有任何「请填写 / 模板 / 请写明」字样或写给运营者的指令。
- **Given** 打开 `/about`，**When** 阅读，**Then** 能知道谁在运营、为什么做、内容如何生产（含 AI 使用披露）、如何更正与下架。
- **Given** 切换到英文版，**When** 点 About/Privacy/Terms，**Then** 得到英文页面（不是 404、不是中文页）。

**独立测试**：脚本抓取 12 类页面 + 中英文政策页，断言链接存在、占位词为 0、邮箱可见。

### 2.2 场景 2 — 审核者抽查任一被索引页面，内容都有「人类编辑的附加价值」（P1）

作为审核者，我从 sitemap 随机点开页面，不应看到「只有一段模型摘要 + 外链」的自动生成页。

- **Given** sitemap 中任意事件页，**When** 打开，**Then** 该事件**有 2 篇以上报道**，或页面带编辑确认的补充内容；单来源且综述过短的事件页不在 sitemap。
- **Given** 一篇公开且有实际摘要的报道，**Then** 默认可被索引并进入 sitemap；人工策展是可选的品质标记，不是索引前置条件。
- **Given** 某天的公开内容，**When** 编辑进入后台按日审核入口，**Then** 可以逐条或整批确认/排除当日新增的精选事件与条目，并留下确认记录。
- **Given** 同一批已发布条目，**Then** 推荐理由没有跨条目复用同一句的情况。

**独立测试**：DB 查询 + sitemap/`noindex` 爬取比对 + 40 页抽样；推荐理由 100 条去重检查。

### 2.3 场景 3 — 读者能看到署名的原创分析（P2）

作为读者，我应当能在聚合之外看到本站自己的分析，并知道是谁写的、用了什么方法与数据。

- **Given** 打开 `/research`，**Then** 至少有 3 篇原创分析；每篇显示作者、发布时间、方法与数据来源。
- **Given** 打开一篇原创分析，**Then** 版式与聚合页明确区分，带 `Article` 结构化数据，可被搜索索引并进入 sitemap。
- **Given** 打开一个聚合事件页，**Then** 仍能看到「AI 综述/AI 根据报道生成」标注与原文链接，不冒充原创。

**独立测试**：页面抓取 + 结构化数据校验 + sitemap 收录检查。

### 2.4 场景 4 — 技术面符合 AdSense 就绪清单（P2）

作为审查者，我愿意把站点加入 AdSense 并完成所有权验证。

- **Given** 访问 `http://` 或 apex 域名，**Then** 301 到 `https://www.livingruntime.com/`；响应带 HSTS。
- **Given** 验证开关关闭（默认），**Then** `/ads.txt` 返回 404，页面无任何 AdSense/广告脚本。
- **Given** 验证开关开启并配置真实 publisher ID，**Then** `/ads.txt` 返回 200 且内容为 `google.com, pub-<16位>, DIRECT, f08c47fec0942fa0`，`<head>` 恰好一条 `google-adsense-account` meta。
- **Given** 站点被提交审核，**Then** 页面仍不加载 `adsbygoogle.js`；广告运行时只在通过审核后、由独立规格与独立开关开启。

**独立测试**：`scripts/adsense-smoke.mjs` 两态验证 + 入口/响应头/sitemap 脚本检查。

### 2.5 边界情况（Edge Cases）

- **安静日/无新事件**：不产生空页面、空策展批次；日报照常出刊（沿用现行安静日规则）。
- **模型综述失败**：页面照常可读（不因缺综述 500），但**不进入索引**（没有可展示的编辑价值）。
- **英文稿缺失或被编辑排除**：英文页 `noindex`、不进 sitemap，且不输出 hreflang 指向。
- **来源下架/撤回**：页面与对应策展记录一起下线；已索引 URL 返回正确状态（410/404 或 noindex），不保留空壳页。
- **规则收紧前已索引的旧页**：统一转为 `noindex` 并从 sitemap 移除；送审前留出重抓窗口（社区经验 2–4 周，未证实）。
- **运营者信息未填齐**：发布前置检查（preflight/smoke）直接失败，不允许带占位符上线或提交审核。
- **EEA/UK/CH 流量**：未配置认证 CMP 时不投放个性化广告（本规格只要求「广告上线前配置」，不实现广告运行时）。

## 3. 需求（Requirements）

### 3.1 功能需求（Functional Requirements）

**合规与身份**

- **FR-001** 中英文 `/privacy` 与 `/terms` 必须完整：运营主体、联系邮箱、生效日期、版本；**不得**含「请填写 / 模板 / 请写明」等占位或操作指令；必须披露 Google 及第三方广告可能使用的 Cookie/标识符与退出方式（广告上线前的表述）。
- **FR-002** 所有公开页面（中英文，含首页、列表、详情、日报、主题、关于、更新日志）的页脚必须包含「隐私说明 / 使用规则 / 联系我们」；从首页一次点击可达。
- **FR-003** 站点必须公开一个可核验的联系邮箱，出现在关于页、隐私页、页脚、`llms.txt` 与 Agent 使用说明中；反馈表单保留但不再是唯一渠道。
- **FR-004** 关于页必须说明运营者身份（个人真名或组织）、建站目的、内容生产与编辑流程、AI 使用披露、更正与下架流程，并链接原创研究栏目。
- **FR-005** 英文版必须提供可访问的英文政策页（`/en/privacy`、`/en/terms`），英文页脚含政策与联系链接；英文页面不得再跳到中文政策页而没有英文入口。

**策展与索引**

- **FR-006** 公开且有内容的 editorial 条目默认允许索引并进入 sitemap，无需精选或编辑批准；人工排除仍优先，撤回、非公开、非内容页保持不索引。
- **FR-007** 每次确认必须留下可审计记录：确认人、确认时间、页面或批次；支持撤销。
- **FR-008** 后台必须提供按日策展入口：一次展示当日新增的精选事件与条目（含 AI 综述/推荐理由），支持逐条或整批确认/排除。
- **FR-009** 索引排除无法提供内容的页面：单来源且 AI 综述少于 100 字的事件页保持跳转至来源条目，不单独进 sitemap；无摘要条目、错误页、反馈页、空状态页不索引。具有有效摘要的独立报道可索引。
- **FR-010** sitemap 必须与索引一致：只列可索引页面；每页有 `lastmod`；URL 与 canonical 一致（去尾斜杠）；不得包含 404 或 `noindex` URL。
- **FR-011** 推荐理由不得在同一发布批次内跨条目复用同句；检测到重复时改写或置空。
- **FR-012** 英文条目或事件具有与当前输入一致的真实英文标题与摘要时可索引（不要求人工批准或同事件两篇以上报道）；英文内容缺失、过期或被人工排除时仍 `noindex`、不进 sitemap。

**原创内容**

- **FR-013** 站点必须有原创研究栏目：`/research` 列表 + 文章页；每篇显示作者、发布时间、方法与数据来源、结论与限制。
- **FR-014** 送审前至少发布 3 篇原创分析，其中至少 1 篇使用站内独家数据（热度/图谱/来源分布等）并配可核对的图表或数据。
- **FR-015** 原创页与聚合页必须在版式、署名与结构化数据上明确区分：聚合页保留 AI 生成标注与原文链接；原创页标注作者、方法与审校；不在同一 URL 混用两类内容。
- **FR-016** 原创文章页必须可索引、进 sitemap，并带 `Article` 结构化数据（作者、`datePublished`、`dateModified`）。

**技术就绪与验证**

- **FR-017** 单一规范主机：`http://` 与 apex 域名的所有公开路径必须 301 到 `https://www.livingruntime.com/`；响应带 HSTS；canonical/og/sitemap 全部使用同一主机。
- **FR-018** 修复重复标题与 canonical 缺陷：`/topics`、`/knowledge` 等页面不得出现双品牌标题；`/daily` 等列表页 canonical 不带尾斜杠，且与 sitemap 一致。
- **FR-019** `robots.txt` 必须显式允许 `Mediapartners-Google` 与 `Google-Display-Ads-Bot`；政策页不得被 `Disallow`；AdSense 爬虫可抓取公开内容。
- **FR-020** AdSense 所有权验证必须由开关控制：开启且 publisher ID 合法时 `/ads.txt` 返回 200 与 Google 卖家记录、`<head>` 恰好一条 meta；关闭或 ID 非法时 `/ads.txt` 返回 404，且任何页面都不出现 AdSense 脚本；配置变更后 api 与 web 两个服务都生效。
- **FR-021** 广告开启前必须配置 Google 认证 CMP（EEA/UK/CH），隐私页写明实际广告服务、Cookie、保留期限与撤回方式。
- **FR-022** 改动必须按 `feature → develop → main` 晋级并部署到生产域名；部署前备份，部署后运行 AdSense smoke 与 production smoke；默认关闭与开启验证两种配置都必须通过。
- **FR-023** 站点审核通过前不得加载 `adsbygoogle.js` 或任何广告位；广告运行时由独立规格定义，带独立开关与测试。

### 3.2 关键实体（Key Entities）

- **策展决定（Curation decision）**：页面或批次、确认人、确认时间、结果（收录/排除）、可撤销。
- **原创文章（Research article）**：slug、标题、作者、发布时间、方法与数据来源、正文、语言；与聚合条目互不混同。
- **政策页内容（Policy page）**：语言、版本、生效日期、运营主体、联系方式。
- **AdSense 验证配置**：开关、publisher ID、`/ads.txt` 记录；与广告运行时严格分离。

## 4. 规格化验收条件

等级：**S1** = 可由脚本/自动化重复验证；**S0** = 送审前必须人工完成或需真实生产数据验证。

| ID | 等级 | 审核者/读者可观察的验收行为 | 检验方式 |
|---|---|---|---|
| AD-01 | S1 | 中英文 `/privacy`、`/terms` 占位词为 0，且含运营主体、联系邮箱、生效日期、版本 | 脚本断言 + 人工复核 |
| AD-02 | S1 | 12 类公开页面（中英）页脚都有「隐私/使用规则/联系我们」，首页一次点击可达 | 抓取扫描 |
| AD-03 | S1 | 联系邮箱在关于页、隐私页、页脚、`llms.txt`、Agent 说明中出现 | 抓取断言 |
| AD-04 | S1 | `/en/privacy`、`/en/terms` 返回 200，可从英文页脚到达 | 抓取 |
| AD-05 | S1 | 未策展页面全部 `noindex` 且不在 sitemap；策展页面可索引 | DB + 爬取比对 |
| AD-06 | S1 | 后台按日策展可完成确认，记录含确认人与时间，可撤销 | 操作 + DB 查询 |
| AD-07 | S1 | sitemap 只含可索引页：0 个 404/`noindex`，100% 有 `lastmod`，URL 与 canonical 一致 | 脚本 |
| AD-08 | S1 | 抽 40 个 sitemap 事件页：0 个单来源且综述少于 100 字 | 固定 seed 抽样 |
| AD-09 | S1 | 抽 100 条推荐理由：0 个跨条目重复 | 脚本 |
| AD-10 | S1 | 未确认的英文页 0 个在 sitemap | 脚本 |
| AD-11 | S1 | `/research` 至少 3 篇；每篇有作者、方法、来源；`Article` 结构化数据校验通过 | 抓取 + 校验 |
| AD-12 | S1 | `http://` 与 apex 全部 301 到 `https://www`；有 HSTS；canonical 一致 | 脚本 |
| AD-13 | S1 | `/topics`、`/knowledge` 无双品牌标题；`/daily` canonical 无尾斜杠 | 脚本 |
| AD-14 | S1 | 验证开关关闭：`/ads.txt` 404、无广告脚本；开启：200 + 唯一 meta + 正确卖家记录 | AdSense 验证 smoke（关闭/开启两态） |
| AD-15 | S1 | `robots.txt` 显式允许 AdSense 爬虫，政策页未被 `Disallow` | 抓取断言 |

## 5. 成功标准（Success Criteria）

- **SC-001 合规面 100%**：AD-01～AD-04 全过；政策页与英文政策页 0 占位词、0 缺失链接。
- **SC-002 索引质量**：sitemap 中 100% 页面满足收录规则；抽 40 页 0 例外；单来源短事件页 0 个。

- **SC-006 送审状态**：AdSense 站点状态为 `Ready for review` 且账户 setup 完成；审核期间页面无 `adsbygoogle.js`。

## 7. 假设、依赖与待使用者确认的输入

### 7.1 假设

- 运营者提供真实身份与联系方式，并对隐私政策/使用条款的准确性负责。
- 站点已有或可创建 AdSense 账号与 publisher ID；Search Console 可用。
- 运营者拥有 Cloudflare 与生产环境的发布权限，发布流程沿用现有 `feature → develop → main` 与部署脚本。
- CMP 采用 Google 自家「Privacy & messaging」（默认）；如选第三方认证 CMP，隐私页文案同步调整。
- 复用现有后台「内容收录/排除」能力扩展为按日策展，不另造内容审核系统。
- 站点继续以公开 RSS/网页为信源，默认只展示摘要与原文链接。
- 站点主要读者不在中国大陆；若主要流量来自大陆，AdSense 的实际收入预期极低（大陆流量基本加载不出 Google 广告，推断/未证实），需另行评估变现方式。此判断不影响本规格的合规整改。

### 7.2 待使用者确认的输入（未确认前按括号内默认值执行）

1. **运营主体**：个人真名或组织名（必须由使用者提供，不得留空）。
2. **公开联系邮箱**：用于页脚、关于页、隐私页、`llms.txt`（必须由使用者提供）。
3. **政策生效日期与版本号**：以实际发布时间填写。
4. **CMP 选择**：Google 自家（默认）或第三方认证 CMP。
5. **英文版策略**：补齐 `/en` 政策页并保留英文索引（默认）；若选择暂不维护英文，则送审期 `/en` 整体 `noindex` 并移出 sitemap。
6. **原创栏目形态**：独立 `/research` 栏目（默认）；至少 3 篇，其中 1 篇独家数据。

### 7.3 依赖

- 政策文本、运营者信息与邮箱由使用者提供；本规格只定义「填什么、不能留什么」。
- 原创文章内容由使用者（或使用者审核后的 AI 协助）撰写；本规格只定义栏目形态、署名与验收。
- AdSense 账户状态、Search Console、Cloudflare 配置与生产发布权限。

## 9. 时间与预期（推断，非验收条件）

- **整改节奏**：P1 合规与身份 1–2 天（内容为主）→ P2 策展/索引/技术 1–2 周 → 原创内容 2–4 周 → 稳定更新 4–8 周 → 提交审核。
- **通过概率（推断）**：以现状直接申请 <10%；完成本规格 P1+P2 后约 10–25%；持续原创输出 3–6 个月后约 30–50%。
- **审核时长**：官方通常几天，特殊情况下 2–4 周；被拒后至少整改 4 周并等待重抓再提，不要以相同状态反复提交。
- **并行变现**：API/MCP/Agent Markdown 订阅与授权、数据报告、赞助/会员，不依赖 AdSense 审核结果。
