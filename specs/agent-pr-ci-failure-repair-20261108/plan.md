# Implementation plan — same-PR CI repair using existing GitHub-native lifecycle

## Evidence and required ordering

The current #501/Issue #491 T002 PR is a real open `agent-work` PR with a failing Check workflow (Run 42438923985, Typecheck TS2559); the existing queue continuation skipped later Work due to `Open agent-work PR; no parallel dispatch`. Therefore a Producer-created Worker task **cannot install the initial repair workflow** while #501 is still blocking that queue.

0. **After independent Spec approval / merge to develop, one-time out-of-queue control-plane bootstrap**: a standard non-`agent-work` feature PR referencing this approved Spec, changing only existing native CI event handling, the official GH-AW same-PR repair workflow/lock generated with pinned v1.0.1 `gh aw compile --strict`, and focused tests. No direct edits to #501 app/test files, migration, work queue ledger, model provider, or review gates. No second queue, cron, runner or self-built model executor.
1. **Normal checks / default branch activation**: Check, Docker, E2E and independent code review must approve the bootstrap feature PR; existing native auto-merge lands it in develop. The workflow_run event entry must then reach GitHub's default branch through a normal reviewed `develop -> main` Merge Commit, not a direct push or an exceptional release bypass. A past failure event is not assumed to re-fire.
2. **Prove actual first repair**: trigger/replay the failed current-head Check for #501 once through an authorized GitHub-native event/dispatch, validate exact repo, PR, SHA, immutable #491 Spec and original PR label; the official GH-AW `push-to-pull-request-branch` handler must push a bounded repair to that **same PR branch**. Confirm the new HEAD causes a real Check run (use official CI-trigger token mechanism if needed), resolves TS2559, and gets genuine Check/Docker/E2E/review success and native develop auto-merge. Verify VM13 preview, using the **original #491/T002 product acceptance contract**, not a new #477 product requirement.
3. **Post-bootstrap native Work**: only after #501 releases the single-open-agent-PR slot can the already existing Producer queue dispatch T001 (focused follow-up regression/observability coverage). T001 must not reimplement the bootstrap or create another #501 PR. The same native continuation then advances other eligible approved original Work (#477, #490) when allowed by the native queue.
4. **Strict event trust and failure classes**: a `workflow_run completed + failure` for the entire Check workflow (failed `check`, `docker`, `e2e` or `claude-review` job); must match same-repo `agent-work` PR to develop, current head, original Issue/Task/Spec. Distinguish actionable code/test blockers from transient runner, container registry, model credentials/quota failures; the latter are visible operator blockers, never fake code-repair submissions. De-duplicate by PR and failing SHA; maximum two repair attempts; keep protected files forbidden.
5. **Regression and delivery evidence**: cover failed Typecheck, Docker-only, E2E-only, actual code-review finding, infrastructure failure, duplicate/old SHA, fork/Draft/other label, attempt cap, no changes, CI-trigger truth, and ordinary native queue continuation. Normal feature/Work PR checks and owner-approved Spec contract remain mandatory.

T001 exists in `tasks.md` only as post-bootstrap work and is automatically generated through the existing Producer. **The one-time non-agent bootstrap is not a Work item and does not use the blocked queue**; do not add T000 as an ordinary Work Graph task.

No direct main push, no direct production host actions, and no bypass of release CI; control-plane workflow source must reach default branch through the existing normal release path.
