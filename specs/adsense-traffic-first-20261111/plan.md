# Plan — AdSense 根据真实访客优先布置新闻详情

## 现有能力与差异

- 复用 #559 / #564 已批准并在执行的空研究页治理、原 AdSense 验证元数据、robots/sitemap、`docs/adsense-readiness.md`、现有 `adsense-preflight` 与 `adsense-smoke`。这次**只更改广告候选/位置和对应文档检查**。
- 连接 Cloudflare GraphQL RUM 的 7 天真实测量（2026-11-04—11-11 UTC）显示新闻详情 501 page loads，高于事件 110、首页 70、日报/周报详情 12；探索 341 与实体 422 有自动化浏览风险。不要再按 /explore 的 HTTP Requests 榜单分配广告。
- 现有新闻阅读组件 `apps/web/app/routes/item.tsx` 的 `briefText`、`reasonText`、`ItemExplainer`、`EventContext` 可作为判断独立阅读价值的线索，**不是机器自动批准**。人工审核/策展凭据需先查看已有后台能力，缺少证据则保留不投放。

## 实施顺序

1. 首先核对当前 `develop`、issue #564、其 Worker 实现 PR 是否已启动/合并。不得与 #564 同时修改相同代码或篡改该不可变任务合约；对已有变更做差异补丁。
2. 更新 `docs/adsense-readiness.md` 广告布局策略：新闻详情是第一候选、首页是有内容/编辑证据时的第二候选、事件次级、研究日报补充；知识实体待核、探索不投；写明绝不因为 UA 爬虫请求量高而投入展示。
3. 对新闻详情规定 1 个固定**未来**广告位的位置（导读/实质独立解释和事件背景之后，来源与交互按钮的安全距离）；对仅短摘要/转述/链接页/英文不完整页/无实际策展证据强调禁投，首页纯导航卡片禁投。仅写政策，不增加广告组件或 JS。
4. 复用已有 smoke/preflight（必要时增加小型断言），覆盖本次申请前页面与 SPA 路由没有 ad-serving 脚本或网络请求；不要把仅 AdSense 验证元标签误报为广告请求。全站空/500/后台/登录/英文/移动保持原零请求约束。
5. 记录 Cloudflare 数据统计口径及自动化浏览不确定性、AdSense 账户 Auto ads/CMP/CDN 注入状态是否已实际核查。未核查写 UNVERIFIED，不得伪造人工审看证明或 Google 审核通过。
6. 等旧 #564 代码在 develop 进入可复用状态后，在**同一最新 develop**做唯一 Worker PR；依靠现有 GH-AW 原生串行、独立审查、CI 通过自动合并；验证新镜像 VM13 预览，保留 `main` 与生产不变。

## 交付边界与不做的事

- 不创建自研分析面板、广告服务、模型流程、数据库迁移、定时器；不放宽 #564 针对空白页的严格禁投。
- 本任务更改的是**获批后预期放在哪里**，不是现在就开始加载广告。启用广告需另行授权并核实 Google AdSense 账户及地区合规条件。
- 如果 #564 还在排队，新任务不得为抢进度另开相同功能的并行 Agent PR，只能在规范顺序下接力。
